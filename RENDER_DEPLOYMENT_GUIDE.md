# Complete Guide: Deploying EthnoKG on Render

This guide provides end-to-end instructions for deploying the **EthnoKG** ethnopharmacological knowledge discovery platform to **Render** using native cloud services.

Render is the **exclusive hosting platform** for this deployment, hosting:
1. **Render PostgreSQL**: Managed relational persistence for plants, relationships, compounds, conditions, documents, and audit logs.
2. **Backend Web Service (`ethnokg-backend`)**: Python 3.11 FastAPI REST API with in-memory NetworkX knowledge graph, PyPDF text extraction, and grounded RAG query assistant.
3. **Frontend Web Service (`ethnokg-frontend`)**: React 19 + Vite + Tailwind CSS v4 Single Page Application with Cytoscape.js interactive graph and Recharts analytics.

## 3. Step-by-Step Deployment Instructions

### Step 1: Push Repository to GitHub

Ensure all configuration files are committed and pushed to your GitHub repository:

```bash
git add .
git commit -m "chore: prepare production deployment configuration for Render"
git branch -M main
git remote add origin https://github.com/<YOUR_GITHUB_USERNAME>/ethnokg.git
git push -u origin main
```

---

### Step 2: Deploy via Render Blueprint (`render.yaml`) — Recommended

EthnoKG includes a fully automated `render.yaml` Blueprint that provisions the PostgreSQL database, backend service, and frontend service in one click.

1. Log in to the [Render Dashboard](https://dashboard.render.com/).
2. In the top navigation bar, click **New +** and select **Blueprint**.
3. Connect your GitHub account and select your `ethnokg` repository.
4. Render will detect `render.yaml` and display the resources to be created:
   - **`ethnokg-db`** (PostgreSQL Database)
   - **`ethnokg-backend`** (Python Web Service)
   - **`ethnokg-frontend`** (Node.js Web Service)
5. Under **Environment Variables**, you will see:
   - `SECRET_KEY`: Automatically generated by Render (`generateValue: true`).
   - `DATABASE_URL`: Automatically linked to `ethnokg-db`.
   - `FRONTEND_URL`: Automatically linked to `ethnokg-frontend`.
   - `VITE_API_URL`: Automatically linked to `ethnokg-backend`.
   - `GEMINI_API_KEY`: *(Optional)* Enter your Gemini key or leave blank.
   - `OPENAI_API_KEY`: *(Optional)* Enter your OpenAI key or leave blank.
6. Click **Apply**.
7. Render will automatically:
   - Provision the PostgreSQL database.
   - Build the backend, run `alembic upgrade head`, seed the initial verified botanical records, and start Uvicorn.
   - Build the frontend (`npm run build`) and start `serve -s dist`.

---

### Step 3: Manual Setup (Alternative to Blueprint)

If you prefer to configure each service individually in the Render UI:

#### A. Create the PostgreSQL Database
1. Click **New +** > **PostgreSQL**.
2. Set **Name**: `ethnokg-db`.
3. Set **Database**: `ethnokg`.
4. Set **User**: `ethnokg_user`.
5. Set **Region**: `Oregon (US West)` (or closest to you).
6. Set **Plan**: `Free`.
7. Click **Create Database**.
8. Once provisioned, copy the **Internal Database URL** (e.g. `postgres://ethnokg_user:...@dpg-...-a/ethnokg`).

#### B. Create the Backend Web Service
1. Click **New +** > **Web Service**.
2. Connect your GitHub repository.
3. Configure the service settings:
   - **Name**: `ethnokg-backend`
   - **Region**: Same region as database (e.g. `Oregon`)
   - **Branch**: `main`
   - **Root Directory**: `backend`
   - **Runtime**: `Python`
   - **Build Command**: `pip install -r requirements.txt && alembic upgrade head`
   - **Start Command**: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - **Plan**: `Free`
4. Expand **Advanced** and set:
   - **Health Check Path**: `/api/health`
5. Add the following **Environment Variables**:
   | Key | Value | Notes |
   | :--- | :--- | :--- |
   | `DATABASE_URL` | *(Paste Internal Database URL from Step A)* | EthnoKG automatically normalizes `postgres://` to `postgresql://` |
   | `ENVIRONMENT` | `production` | Enables production mode |
   | `APP_NAME` | `EthnoKG` | Display name |
   | `SECRET_KEY` | *(Click "Generate" or enter 32+ random chars)* | Session security |
   | `DEFAULT_CONFIDENCE_THRESHOLD` | `0.75` | Minimum NLP extraction confidence |
   | `FRONTEND_URL` | `https://ethnokg-frontend.onrender.com` | Update once frontend is created |
   | `CORS_ORIGINS` | `["https://ethnokg-frontend.onrender.com","http://localhost:5173"]` | Allowed web origins |
   | `USE_LLM_EXTRACTION` | `false` | `false` uses offline hybrid NLP engine |
   | `GEMINI_API_KEY` | *(Optional)* | Optional Gemini API key |
   | `OPENAI_API_KEY` | *(Optional)* | Optional OpenAI API key |
6. Click **Create Web Service**.

#### C. Create the Frontend Web Service
1. Click **New +** > **Web Service**.
2. Connect the same repository.
3. Configure service settings:
   - **Name**: `ethnokg-frontend`
   - **Region**: Same region as backend (e.g. `Oregon`)
   - **Branch**: `main`
   - **Root Directory**: `frontend`
   - **Runtime**: `Node`
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm run start`
   - **Plan**: `Free`
4. Add the following **Environment Variables**:
   | Key | Value | Notes |
   | :--- | :--- | :--- |
   | `NODE_VERSION` | `22.12.0` | Node runtime version |
   | `VITE_API_URL` | `https://ethnokg-backend.onrender.com` | Points to your Render backend service |
5. Click **Create Web Service**.

6. **Evidence Explorer**: Filter claims across the 6 scientific evidence tiers.

8. **Verification Workspace**: Inspect pending literature claims, review verbatim supporting excerpts, and execute approve/reject actions with audit history.

10. **Sources & Ethics**: Confirm transparent attribution for Royal Botanic Gardens Kew MPNS, WFO, PMC Open Access, PubChem, ChEMBL, GBIF, and BHL.

## 5. Troubleshooting Common Render Deployment Issues

### Issue 1: SQLAlchemy rejects `postgres://` URL
- **Symptom**: `NoSuchModuleError: Can't load plugin: sqlalchemy.dialects:postgres`
- **Root Cause**: Render generates database URLs starting with `postgres://`, but SQLAlchemy 2.0 requires `postgresql://`.
- **Solution**: Already handled in `backend/app/core/config.py` via `get_normalized_database_url()`. If configuring manually, replace `postgres://` with `postgresql://`.

### Issue 2: `ModuleNotFoundError: No module named 'psycopg2'`
- **Symptom**: Backend build or startup crashes during database engine creation.
- **Root Cause**: Missing PostgreSQL client driver.
- **Solution**: Already added to `backend/requirements.txt` (`psycopg2-binary>=2.9.9`).

### Issue 3: Stale Database Connections
- **Symptom**: `OperationalError: SSL connection has been closed unexpectedly` after inactivity.
- **Root Cause**: Render terminates idle TCP connections.
- **Solution**: Already resolved in `backend/app/core/database.py` with `pool_pre_ping=True` and `pool_recycle=300`.

### Issue 4: CORS Errors on Frontend
- **Symptom**: Browser console logs `Access to fetch at '...' has been blocked by CORS policy`.
- **Root Cause**: Frontend Render domain not included in backend CORS allowed origins.
- **Solution**: EthnoKG backend automatically permits all `*.onrender.com` domains using `allow_origin_regex=r"^https://.*\.onrender\.com$"`, in addition to `FRONTEND_URL` and `CORS_ORIGINS`.

### Issue 5: 404 on Page Refresh in Frontend
- **Symptom**: Navigating directly to a sub-route or refreshing causes a 404 error.
- **Root Cause**: Static web servers look for physical file paths instead of rewriting to `index.html`.
- **Solution**: EthnoKG uses `serve -s dist -l $PORT` in `package.json` (`-s` enables Single Page Application fallback) and includes `frontend/public/_redirects`.

### Issue 6: Render Free Tier Cold Starts
- **Symptom**: Initial request takes 30-50 seconds to respond.
- **Root Cause**: Render free instances spin down after 15 minutes of inactivity.
- **Solution**: This is expected behavior on Render free tier. To eliminate cold starts, upgrade services to the `Starter` plan ($7/mo) in the Render dashboard.

## 6. Security Checklist for Production

- [x] No secrets or API keys committed to git (`.gitignore` protects all `.env` files).
- [x] Database password and connection string stored strictly in Render environment variables.
- [x] Render PostgreSQL isolated on internal private network.
- [x] Database connection pooling uses SSL and pre-ping checks.
- [x] CORS restricted to authenticated origins and Render app subdomains.
- [x] File uploads processed in-memory via PyPDF with text extraction; zero executable file uploads permitted.
- [x] RAG research assistant enforces zero-hallucination constraint and mandatory non-medical research disclaimer.
